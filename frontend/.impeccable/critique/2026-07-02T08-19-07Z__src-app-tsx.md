## Anti-Patterns Verdict

**LLM assessment:** หน้าจอมีความเป็น AI-generated template ระดับปานกลางถึงสูง แม้ใช้งานได้และเข้ากับหมวด HR แต่ composition เป็นสูตร admin dashboard ที่คุ้นเกินไป: sidebar สีขาว, โลโก้ gradient, metric cards ขนาดเท่ากันสามใบ, table อยู่ใน card ใหญ่ และ note ท้าย sidebar จุดเหล่านี้ทำให้งานดูเหมือน demo ที่ขัดเงาแล้ว มากกว่าระบบ HR ที่ออกแบบจากงานจริง

**Deterministic scan:** detector รันกับ `src/App.tsx` สำเร็จ ได้ผล `[]` จำนวน 0 findings ไม่มี rule หรือ file location ที่ต้องรายงาน และไม่มี false positive ผลนี้หมายถึงไม่พบ anti-pattern ที่ detector ตรวจแบบ deterministic ได้ ไม่ได้หักล้างปัญหาเชิง composition/workflow ที่ design review พบ

**Visual overlays:** ไม่มี overlay ที่เชื่อถือได้ เนื่องจาก browser runtime ไม่พบ in-app browser surface (`iab`) และรายการ browser surfaces ว่าง จึงไม่ได้เริ่ม live server, ไม่ inject `detect.js` และไม่อ้างว่ามีผล console/overlay

## Overall Impression

ระบบมีลำดับชั้นชัด ภาษาไทยดี งาน CRUD หลักค้นพบได้เร็ว และ state coverage ดีกว่างานทดสอบทั่วไป โอกาสใหญ่ที่สุดคือเปลี่ยนจาก “dashboard demo” ให้เป็น “เครื่องมือ HR รายวัน”: ทำงานซ้ำให้เร็วขึ้น, ทำ destructive actions ให้ปลอดภัยขึ้น และแบ่งฟอร์มตามภาษางาน HR แทนการวาง field ทั้งหมดพร้อมกัน

## What’s Working

1. **เข้าใจงานหลักได้ทันที:** เมนูมีเพียงพนักงาน/แผนก ปุ่มเพิ่ม Search และ Filter อยู่ในตำแหน่งที่คาดเดาได้
2. **Localization ตรงโดเมน:** ภาษาไทย วันที่ พ.ศ. รหัสพนักงาน ตำแหน่ง แผนก และสถานะตรงกับสิ่งที่ HR ใช้จริง
3. **มี state foundation ที่ครบ:** รองรับ loading, empty, success, error, saving-disabled และกรณียังไม่มีแผนก ไม่ได้เป็นเพียง static mockup

## Priority Issues

### [P1] การลบข้อมูลยังไม่ปลอดภัยพอ

- **Why it matters:** การลบพนักงาน/แผนกเป็นงานความเสี่ยงสูง แต่ native confirm แสดงเพียงชื่อ ไม่มีจำนวนพนักงานที่เกี่ยวข้อง ผลกระทบ ความถาวร หรือ undo
- **Fix:** ใช้ shadcn AlertDialog ให้สม่ำเสมอ แสดงผลกระทบโดยเฉพาะ employee count ของแผนก ใช้ข้อความ destructive ที่ชัดเจน และเพิ่ม undo หาก backend รองรับ
- **Suggested command:** `$impeccable harden`

### [P1] ฟอร์มพนักงานเป็นกำแพง 13 controls

- **Why it matters:** ผู้ใช้ต้องประมวลผล identity, employment, contact, address, photo และ status พร้อมกัน เกิน working-memory guideline และทำให้งานง่ายรู้สึกเป็นงานเอกสาร
- **Fix:** แบ่งเป็น 3–4 section ได้แก่ ข้อมูลประจำตัว, ข้อมูลงาน, ช่องทางติดต่อ และข้อมูลเสริม ย้ายที่อยู่/รูปไป optional section และรักษา action bar ให้มองเห็นเมื่อ scroll
- **Suggested command:** `$impeccable distill` หรือ `$impeccable layout`

### [P1] งาน HR จำนวนมากยังต้องทำทีละรายการ

- **Why it matters:** ไม่มี sort, multi-select, bulk status, pagination หรือ keyboard accelerator เมื่อมีพนักงานหลายร้อยคน การบำรุงข้อมูลจะช้า
- **Fix:** เพิ่ม sortable columns, row selection, bulk status action, `/` เพื่อ focus search และ pagination/virtualization ตาม scale ที่คาดไว้
- **Suggested command:** `$impeccable shape`

### [P2] Error feedback ยังไม่ชี้ทางแก้

- **Why it matters:** DOB/join date และ server errors แสดงรวมใน banner ผู้ใช้ไม่รู้ทันทีว่าต้องแก้ field ใด
- **Fix:** ใช้ field-level message, `aria-describedby`, focus field แรกที่ผิด, แปล backend error เป็นไทย และเพิ่ม in-place retry เมื่อโหลดข้อมูลล้มเหลว
- **Suggested command:** `$impeccable clarify` หรือ `$impeccable audit`

### [P2] Dashboard chrome แย่งพื้นที่จากงานหลัก

- **Why it matters:** metric cards สามใบปรากฏเหมือนกันทั้งสองหน้า ขณะที่ sidebar note และโลโก้ gradient เพิ่ม template feel แต่ไม่ได้ช่วยตัดสินใจ
- **Fix:** ลดหรือย้าย metrics ให้ใกล้ context และทำให้ actionable เช่น “พนักงานพ้นสภาพ” หรือ “ข้อมูลไม่ครบ” ตัด sidebar note และใช้ brand mark แบบเรียบหากไม่มี identity จริง
- **Suggested command:** `$impeccable distill`

## Cognitive Load

ระดับ **ปานกลาง: fail 3/8 ข้อ**

- Fail: chunking — ฟอร์ม 13 controls ไม่มีการแบ่งกลุ่ม
- Fail: one thing at a time — required/optional และข้อมูลคน/งาน/ติดต่อปะปนกัน
- Fail: progressive disclosure — address และ photo แสดงตลอดแม้ไม่จำเป็น
- Pass: single focus, grouping ระดับหน้า, visual hierarchy, minimal top-level choices และ working-memory ระหว่างหน้า

## Emotional Journey

หน้าแรกให้ความรู้สึกสงบและเป็นระเบียบ Search/Filter สร้างช่วงที่ผู้ใช้รู้สึกควบคุมงานได้ แต่ฟอร์มยาวเป็น emotional valley เพราะคำแนะนำบางและ error มาช้า การลบเป็นจุดเสี่ยงที่สุดแต่กลับใช้ browser confirm ที่ให้ข้อมูลน้อย Success toast ปิดงานได้ดี ทว่า full reload และไม่มี recovery ลดความมั่นใจต่อข้อมูลบุคลากร

## Persona Red Flags

**Alex — Power User**

- ค้นหาและกรองได้เร็ว แต่ sort/multi-select/bulk update ไม่ได้
- ไม่มี shortcut สำหรับเพิ่มรายการหรือ focus search
- งานซ้ำต้องเปิด modal และ reload เต็มทุกครั้ง

**Sam — Keyboard/Screen Reader User**

- ปุ่ม Edit/Delete มีไอคอนแต่ไม่มี accessible name
- Switch กับ Label อยู่ใกล้กันทางภาพ แต่ไม่ได้ผูก association ชัดเจน
- Global form error ไม่มี live-region/field linkage
- Loading ไม่มี announced busy semantics และตารางแนวนอนบนจอแคบทำให้ action context หาย

**Nok — HR Officer**

- ตอนเพิ่มพนักงานเห็น 13 fields โดยไม่มี section/examples
- รู้ว่าขาดวันที่เมื่อ submit แล้ว
- ก่อนลบแผนกไม่เห็น dependency หรือจำนวนพนักงานที่ได้รับผลกระทบ และกู้คืนไม่ได้

## Minor Observations

- Mobile CSS ซ่อน metric ใบที่สาม ซึ่งเป็นการเปลี่ยนข้อมูล ไม่ใช่การ adapt layout
- ใช้ global selectors `header`/`aside` ทำให้ style เปราะเมื่อเพิ่ม semantic elements ใหม่
- Search copy/logic ไม่ครอบคลุมตำแหน่งหรือเบอร์โทร ทั้งที่ HR อาจคาดหวัง
- ควรตรวจ contrast ของ badge เขียวอ่อน
- Action column ไม่มี accessible header
- ใช้ Users icon ซ้ำกับทั้ง total employees และ new employees ทำให้ scan แยกยาก
